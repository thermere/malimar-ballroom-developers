# Security policy

## Scope

This policy covers:

- the public Malimar Ballroom website, including its Developer Mode page;
- the documents in this repository.

The application source is private. If you believe you have found a problem that affects it, report it the same way. The maintainers will handle it privately.

## Reporting a vulnerability

Please report privately. **Do not open a public issue, discussion or pull request** for a security problem.

- **Channel:** use this repository's private vulnerability report form. Open the repository's **Security** tab and choose **Report a vulnerability**. The report goes to the maintainers and is not public.
- Describe the problem, the affected page or file, the steps to reproduce it, and the effect you expect.
- Do not include real keys, tokens, signed links, passwords or personal data in a report. Say where they appear, and the maintainers will arrange a private way to check them.
- Do not test against systems you do not own or have permission to test. Do not access, change or delete other people's data.

## What to expect

The maintainers will acknowledge a report, check it, and discuss a fix and the timing of any disclosure with you. This policy does not promise specific response times. No bounty is offered.

## Public disclosure

Please give the maintainers a reasonable chance to fix a problem before you disclose it publicly. Credit is given if you want it.
